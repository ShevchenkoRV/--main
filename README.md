## Можливості системи

### Для адміністратора

- **Захищений вхід** — доступ до панелі адміністратора закритий паролем (за замовчуванням `1234`).
- **Створення тестів** — зручний конструктор: вводиш назву тесту, потім додаєш питання одне за одним. Кожне питання має рівно 4 варіанти відповіді; правильні позначаються чекбоксами (підтримується кілька правильних відповідей одночасно).
- **Редагування тестів** — тривіконна компоновка: список тестів → список питань → редактор конкретного питання. Можна змінити текст питання, будь-який варіант відповіді або позначку правильної відповіді, а також видалити окреме питання або весь тест (з підтвердженням).
- **Видалення тестів** — видалення каскадне: разом із тестом видаляються всі його питання.
- **Експорт тестів у JSON** — будь-який тест можна зберегти у JSON-файл на диску для резервного копіювання або передачі іншому викладачу.
- **Статистика студентів** — перегляд результатів по кожному студенту: список усіх спроб з назвою тесту та балом, підсумковий середній бал і загальна кількість спроб.

### Для студента

- **Вибір тесту** — прокручуваний список усіх доступних тестів з радіокнопками.
- **Введення імені** — студент вводить своє ПІБ перед початком; ця інформація прив'язується до результату в базі даних.
- **Проходження тесту** — питання відображаються по одному. Для кожного питання є 4 варіанти відповіді у вигляді чекбоксів (можна обрати декілька). Лічильник «Питання X з Y» показує прогрес. Є кнопка «Скасувати» з підтвердженням (прогрес не зберігається).
- **Миттєві результати** — після останнього питання одразу відкривається екран результатів з великим підсумковим балом та кольоровим індикатором: зелений (≥ 90%), жовтий (≥ 60%), червоний (< 60%).
- **Детальна таблиця відповідей** — для кожного питання показано: текст питання, відповідь студента, правильна відповідь, позначка ✔ або ✘.

## Архітектура програми

Програма побудована за патерном **Controller + Frame Stack**:

```
TestingApp (ttk.Window)
│
├── container (ttk.Frame)
│   ├── MainMenu          ←┐
│   ├── AdminMenu          │
│   ├── TestConstructor    │  show_frame(name, **kwargs)
│   ├── EditTest           │  піднімає потрібний Frame поверх стека
│   ├── ExportTestSelection│  і викликає on_show(**kwargs)
│   ├── StudentStatistics* │
│   ├── StudentMenu       ─┤
│   ├── TestTaking         │
│   └── ResultsScreen     ─┘
│
└── test_manager (TestManager)  ← спільний для всіх екранів
```

Усі екрани створюються **один раз** при старті та лежать у `container` один поверх одного. Навігація — це просто `tkraise()` потрібного фрейму. Якщо екран потребує оновлення даних при кожному відкритті, він реалізує метод `on_show(**kwargs)`.

## База даних

Файл `testing_system.db` (SQLite 3) створюється автоматично у тій же папці, де знаходиться `main.py` (або `.exe`).

### Таблиця `tests`

| Поле | Тип | Опис |
|---|---|---|
| `id` | INTEGER PK | Автоінкремент |
| `title` | TEXT NOT NULL | Назва тесту |

### Таблиця `questions`

| Поле | Тип | Опис |
|---|---|---|
| `id` | INTEGER PK | Автоінкремент |
| `test_id` | INTEGER FK | Зовнішній ключ → `tests.id` |
| `question` | TEXT NOT NULL | Текст питання |
| `answer1` | TEXT NOT NULL | Варіант відповіді А |
| `answer2` | TEXT NOT NULL | Варіант відповіді Б |
| `answer3` | TEXT NOT NULL | Варіант відповіді В |
| `answer4` | TEXT NOT NULL | Варіант відповіді Г |
| `correct_answer` | TEXT NOT NULL | Індекси правильних відповідей через кому, напр. `"0"` або `"0,2"` |

> **Примітка:** правильні відповіді зберігаються як рядок з індексами (починаючи з 0). Наприклад, якщо правильні А та В — зберігається `"0,2"`.

### Таблиця `results`

| Поле | Тип | Опис |
|---|---|---|
| `id` | INTEGER PK | Автоінкремент |
| `student_name` | TEXT | ПІБ студента |
| `test_id` | INTEGER | ID тесту |
| `score` | INTEGER | Кількість правильних відповідей |

## Опис екранів

### `MainMenu` — Головне меню

Стартовий екран. Дві кнопки: **«Студент»** і **«Адміністратор»**.

- «Студент» → переходить на `StudentMenu`.
- «Адміністратор» → викликає `prompt_admin_password()`, яка показує діалогове вікно з полем для пароля. При правильному паролі переходить на `AdminMenu`, при хибному — показує повідомлення про помилку.

---

### `AdminMenu` — Панель адміністратора

Навігаційний хаб для адміністратора. Кнопки:

- **Створити тест** → `TestConstructor`
- **Редагувати тест** → `EditTest`
- **Експортувати тест** → `ExportTestSelection`
- **Статистика студентів** → `StudentStatisticsSelection`
- **Вийти** → `MainMenu`

---

### `TestConstructor` — Конструктор тесту

Дворівнева компоновка: ліва колонка (список доданих питань) + права колонка (форма введення).

**Процес створення:**
1. Ввести назву тесту у верхньому полі.
2. Заповнити форму праворуч: текст питання + 4 варіанти відповіді. Позначити правильні чекбоксами (можна кілька).
3. Натиснути **«Додати питання»** — питання з'являється у списку ліворуч, форма очищається.
4. Повторювати кроки 2–3 скільки потрібно.
5. Натиснути **«Зберегти тест»** — тест і всі питання записуються в БД одним пакетом.

> Питання зберігаються в `self.pending_questions` (у пам'яті) до натискання «Зберегти». Якщо закрити екран без збереження — дані губляться.

---

### `EditTest` — Редагування тестів

Три колонки:

| Ліва | Центр | Права |
|---|---|---|
| Список усіх тестів | Питання обраного тесту | Редактор обраного питання |

**Доступні дії:**
- Обрати тест → у центрі завантажуються його питання.
- Обрати питання → у правій колонці заповнюються поля редактора.
- **«Зберегти зміни»** — записує зміни в БД через `UPDATE`.
- **«Видалити питання»** — видаляє обране питання з БД.
- **«Видалити тест»** — видаляє весь тест і всі його питання (з підтвердженням через `messagebox.askyesno`).

---

### `ExportTestSelection` — Експорт у JSON

Список усіх тестів у вигляді кнопок. При натисканні на тест відкривається системний діалог збереження файлу (`filedialog.asksaveasfilename`). За замовчуванням ім'я файлу = назва тесту + `.json`.

---

### `StudentStatisticsSelection` — Список студентів

Список усіх студентів, що здавали хоча б один тест (отримується через `SELECT DISTINCT`). При натисканні → `StudentStatisticsViewer` з ім'ям студента.

---

### `StudentStatisticsViewer` — Деталі по студенту

Таблиця `ttk.Treeview` з колонками:

| Назва тесту | Результат (балів) |
|---|---|
| ... | ... |

Внизу — підсумок: **середній бал** і **загальна кількість спроб**.

---

### `StudentMenu` — Меню студента

Двоетапний вибір:

1. **Вибір тесту** — прокручуваний список радіокнопок.
2. **Введення ПІБ** — текстове поле.

Кнопка **«Почати тестування»** стає активною лише коли обидва поля заповнені (відслідковується через `trace_add` на `StringVar`).

---

### `TestTaking` — Проходження тесту

Питання виводяться по одному. Зверху — лічильник прогресу, під ним — текст питання, нижче — 4 чекбокси з варіантами відповіді.

- **«Далі →»** — зберігає обрані індекси у `self.user_answers` і переходить до наступного питання.
- **«Скасувати»** — з підтвердженням повертає на `StudentMenu` без збереження.
- Після останнього питання автоматично викликається `_finish_test()`, яка передає всі дані на `ResultsScreen`.

---

### `ResultsScreen` — Екран результатів

Відображається одразу після завершення тесту.

**Компоненти:**
- Великий лейбл з балом: `X / Y (Z%)`. Колір залежить від відсотка: зелений ≥ 90%, жовтий ≥ 60%, червоний < 60%.
- Таблиця з детальним розбором кожного питання:
  - № питання
  - Текст питання
  - Відповідь студента (у форматі «А) Варіант, В) Варіант»)
  - Правильна відповідь
  - Позначка ✔ або ✘

- Результат автоматично **зберігається в БД** (`results`) при відкритті екрану.
- Кнопки **«На головну»** і **«Ще раз»** (повертає на `StudentMenu`).

## Збірка у .exe

Для збірки використовується [PyInstaller](https://pyinstaller.org/).

**Встановлення PyInstaller:**

```bash
pip install pyinstaller
```

**Команда збірки (один файл):**

```bash
pyinstaller --onefile --windowed --name TestingApp main.py
```

| Прапор | Призначення |
|---|---|
| `--onefile` | Упакувати все в один `.exe` |
| `--windowed` | Не показувати консоль при запуску |
| `--name TestingApp` | Назва вихідного файлу |

Готовий файл з'явиться у папці `dist/TestingApp.exe`.

> **Увага:** При запуску `.exe` база даних `testing_system.db` створюється у тій же папці, де знаходиться `.exe`, а не у `dist/`. Переконайтесь, що у папці є права на запис.

## Формат JSON для імпорту/експорту

Тест зберігається у наступному форматі:

```json
{
    "test_name": "Назва тесту",
    "questions": [
        {
            "question": "Текст питання?",
            "answer1": "Варіант А",
            "answer2": "Варіант Б",
            "answer3": "Варіант В",
            "answer4": "Варіант Г",
            "correct_answer": "0"
        },
        {
            "question": "Питання з кількома правильними відповідями?",
            "answer1": "Варіант А",
            "answer2": "Варіант Б",
            "answer3": "Варіант В",
            "answer4": "Варіант Г",
            "correct_answer": "0,2"
        }
    ]
}
```

**Поле `correct_answer`** — рядок з індексами правильних відповідей (починаючи з 0), розділених комою:

| Значення | Правильна відповідь |
|---|---|
| `"0"` | А |
| `"1"` | Б |
| `"2"` | В |
| `"3"` | Г |
| `"0,2"` | А та В |
| `"1,3"` | Б та Г |

> JSON-файли, створені через **«Експорт»**, можна редагувати вручну та повторно імпортувати (функція імпорту розробляється як можливе розширення).
